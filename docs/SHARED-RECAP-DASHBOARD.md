# Shared audio and Notes dashboard

The existing `/meeting-ui/dashboard/` library now lists the signed-in owner's audio meetings and handwritten Notes together, with source labels, a source filter, combined status counts and server-side filtering/pagination. Notes review uses `/meeting-ui/dashboard/?view=notes#note-ID`; the existing meeting review flow remains in place. Notes source/recap editing and separate approval are reused. Old Notes links redirect to the shared dashboard view and retain the job fragment, so the installed Function does not need reimporting or valve changes.

Only Notes-enabled, allowlisted accounts receive Notes rows. Disabling the shared Notes feature returns the library to audio-only results. Other owners' content is never included. Notes indexed indicators use the existing last-successful-ingestion ledger and a matching committed approval hash; they do not imply a live Knowledge search.

The Notes session endpoint previously compared the public browser origin with the backend Host header. A reverse proxy rewrites that host, causing `Notes origin does not match this host` before the saved list could load. The endpoint now also accepts an explicitly configured `NOTES_PUBLIC_ORIGIN`, set on this deployment to the existing HTTPS WebUI origin. It does not trust arbitrary forwarded host headers. WebUI identity, owner allowlisting, signed cookie/owner/origin-bound CSRF, unauthenticated refusal and cross-origin write refusal remain enforced.

The UI change touches dashboard HTML/JavaScript and the dashboard listing/asset routes; audio transcription, recap generation, revisions, approval algorithms and ingestion schedule are unchanged. New module `notes_library.py` supplies owner-scoped Notes summaries. `notes_web.py` contains the origin fix. Both the legacy Notes route and the new shared-dashboard view remain supported.

The server requires administrator access for a worker restart to load route changes and the configured public origin. Source/config backups must precede installation; rollback restores code/config only and retains all Notes/meeting records and approved snapshots. Existing Notes model hotfix 1 remains installed. Do not re-upload the recovered four-picture job to resolve a dashboard display problem.

Verification includes the Notes/shared-dashboard suite and all existing offline meeting suites, with new checks for combined counts, pagination, source/search filters, owner and pilot isolation, audio-only fallback, same-route Notes review, explicitly configured public origin behind a rewritten Host, refusal of spoofed forwarded headers, and preservation of origin-bound CSRF. Browser rehearsal verifies both source rows and the Notes Open button. Live authenticated browser confirmation passed after the administrator restart: four audio meetings and one Notes recap appeared together, and the recovered four-picture revision 2 opened without the origin error. Existing Notes links also redirected correctly. All 339 offline package checks passed.
